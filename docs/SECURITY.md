# Hot Potato ERP 보안

> 개발 단계: **④ 구조 생성**(보안 정책) · **⑦ 수정 및 문서화**
> 기준: `main` @ `ffed6c7` (2025-12-01). 이후 보안 개선은 [hot_potato_remake](https://github.com/semicolon213/hot_potato_remake)에서 진행합니다.
> 이 문서는 보안 **설계와 운영 원칙**을 다룹니다. 구체적인 취약점 내용은 공개 저장소에 적지 않습니다([§6](#6-취약점-신고)).

## 1. 인증

| 항목 | 내용 |
|---|---|
| 로그인 | Google OAuth 2.0 (implicit flow, `response_type=token`). 별도 비밀번호를 저장하지 않음 |
| 토큰 저장 | 브라우저 `localStorage`의 `googleAccessToken` (발급·만료 시각 포함). URL 해시로 받은 토큰은 받은 즉시 주소창에서 지움 |
| 토큰 만료 | 만료 1분 전부터 무효로 봄. 30초마다 확인하고, 만료되면 로그아웃 후 다시 로그인을 요구함. 갱신 토큰이 없어 최대 세션은 약 1시간 |
| 무활동 만료 | 30분 동안 마우스·키보드·스크롤·터치 활동이 없으면 로그아웃 |
| 로그아웃 | 저장된 사용자 정보와 토큰을 지우고 Google 자동 선택을 끔. **완전히 로그아웃**을 고르면 그 계정을 최근 로그인 목록에서 지우고 Google 로그인 연결도 해제함 |
| Electron | 앱 종료 직전에 로그아웃 처리 |
| Apps Script 실행 | 배포 계정 권한으로 실행. 공용 데이터는 배포 계정 드라이브에 있음 |

## 2. 접근 제어

### 2.1 가입 단계

1. **사전 등록:** 관리자가 등록한 학번/교번과, Google 계정 이름이 일치해야 가입을 신청할 수 있습니다.
2. **관리자 승인:** 승인 전에는 **승인 대기 중** 화면 외에 아무것도 볼 수 없습니다.
3. **관리자 권한:** `hp_member.user` 시트의 `is_admin` 값으로 정합니다. 매일 바뀌는 관리자 키 기능이 설계돼 있지만, 기준 시점에는 가입 흐름에 반영되지 않아 운영자가 시트에서 직접 부여합니다([OPERATOR_MANUAL.md §3.4](./OPERATOR_MANUAL.md#34-관리자-추가)).

### 2.2 역할별 권한 (화면 기준)

| 기능 | student | std_council | supp | professor | ad_professor | 관리자 |
|---|:-:|:-:|:-:|:-:|:-:|:-:|
| 공지 조회 (공개 범위 내) | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 문서·결재 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 회계 메뉴 | | ✅ | ✅ | ✅ | | |
| 가입 승인, 고정 공지 승인 | | | | | | ✅ |
| 기본 템플릿·기본 태그·결재 템플릿 관리 | | | | | | ✅ |
| 학사 일정 설정 | | | | | | ✅ |

"관리자"는 역할과 별개인 플래그(`is_admin = O`)입니다. 어느 역할이든 관리자일 수 있습니다.

데이터 단위 권한:

| 데이터 | 누가 | 근거 |
|---|---|---|
| 공지 열람 | 공지의 공개 범위에 든 사용자 | `notice.access_rights` |
| 결재 처리 | 현재 단계 담당자 | 결재선 |
| 재상신 | 요청자 본인 | `requester_email` |
| 공지 수정·삭제 | 작성자 본인 | 작성자 정보 |
| 장부 | 장부 생성 시 지정한 사용자·그룹 | Drive 공유 권한 |
| 개인 설정·개인 문서 | 본인 | 사용자 개인 드라이브 |

### 2.3 권한을 지키는 곳

| 경로 | 보호 수단 |
|---|---|
| 브라우저에서 Sheets·Drive 직접 접근 (캘린더, 학생, 교직원, 장부, 개인 설정) | **Google Drive 공유 권한**. 공유받지 않은 파일은 읽을 수 없음 |
| Apps Script 경유 (회원, 공지, 결재, 공유 문서, 태그) | Apps Script 안의 검사 로직 |
| 화면 | 역할·관리자 여부에 따라 메뉴·버튼 표시 (보조 수단. 화면 숨김만으로 권한을 보장하지 않음) |

## 3. 데이터 보호

| 대상 | 보호 방법 |
|---|---|
| 회원 이메일(`user.google_member`), 공지 작성자 이메일(`notice.writer_email`) | 저장 전에 가역 변환(인코딩)을 거침 (`EncryptionEmail.gs`, `EncryptionCore.gs`). 표준 암호화는 아님 |
| 학생·교직원 연락처 | 위와 같은 변환을 Apps Script 액션으로 적용 |
| 관리자 키 | 여러 단계 변환을 거친 값을 `admin_keys` 시트에 저장. 트리거로 매일 교체하고 이전 키는 `admin_keys_backup`에 남김 |
| Apps Script 웹앱 주소 | `VITE_APP_SCRIPT_URL`로 번들에 들어가므로 **공개 값**으로 취급. 운영 환경 API 호출은 Netlify Function 프록시를 거침 |
| 공용 데이터 원본 | 배포 계정 드라이브. 역할 폴더를 해당 그룹에 공유 |

현재 저장 시 변환은 Apps Script 안에 있는 알고리즘 조합입니다. 표준 암호화(키 관리가 분리된 AES 등)로 바꾸는 것을 개선 과제로 둡니다([§5](#5-개선-계획)).

### 공개되는 값

`VITE_`로 시작하는 환경변수는 빌드할 때 브라우저 번들에 들어갑니다. OAuth 클라이언트 ID, Apps Script 웹앱 주소, 폴더·시트 이름, 그룹 이메일이 여기에 해당하며, **공개되어도 되는 값만** 넣습니다. 서버 쪽 그룹 주소(`CONFIG.gs`)도 공개 저장소에 들어 있습니다.

## 4. 운영 보안 수칙

- Apps Script **배포 계정**은 학과 공용 계정으로 하고, 2단계 인증을 켭니다. 이 계정이 모든 공용 데이터의 소유자입니다.
- `hp_member` 스프레드시트는 배포 계정 외에 공유하지 않습니다.
- 역할 폴더는 그 역할의 그룹에만 공유합니다. 개인 계정을 직접 추가하는 것은 최소로 합니다.
- 퇴직·졸업자는 Google 그룹에서 빼고, `user` 시트의 `Approval`을 비웁니다.
- 장부 폴더 공유는 장부 관리인과 필요한 그룹으로만 제한합니다.
- Apps Script와 Netlify Function 실행 로그에는 요청 내용이 남습니다. 로그 열람 권한은 운영 담당자로 제한합니다.
- 시트를 직접 수정할 때 변환된 열을 평문으로 덮어쓰지 않습니다.
- 공용 PC에서는 **완전히 로그아웃**을 쓰도록 안내합니다.

## 5. 개선 계획

코드 점검(2026-10-27)에서 나온 보안 개선 과제의 **분류**입니다. 세부 내용과 우선순위는 비공개로 관리하며, 실제 개선은 [hot_potato_remake](https://github.com/semicolon213/hot_potato_remake)에서 진행합니다.

| 분류 | 방향 |
|---|---|
| 서버 측 인가 | Apps Script가 요청자의 신원을 직접 확인하도록 바꿉니다 (예: ID 토큰 검증). 관리 기능은 모두 서버에서 관리자 여부를 다시 확인합니다 |
| 화면 접근 | 페이지 단위로 권한을 검사합니다. 메뉴 숨김과 브라우저에 저장된 값에만 의존하지 않습니다 |
| 개인정보 저장 | 표준 암호화 방식으로 바꾸고, 복호화는 필요한 서버 로직 안에서만 합니다 |
| 키 관리 | 관리자 키를 암호학적 난수로 만들고, 검증 로직을 하나로 합치며, 가입 흐름과 연결합니다 |
| 비밀 값 관리 | 코드에 들어 있는 기본 URL·키 값을 없애고 환경변수로만 받습니다 |
| 로그인 방식 | implicit flow를 Authorization Code + PKCE로 바꿔 토큰 갱신과 세션 유지 시간을 개선합니다 |
| 오류·로그 | 운영 환경 응답에서 디버그 정보를 빼고, 로그에 개인정보·키가 남지 않게 합니다 |
| 로그아웃 | 로그아웃할 때 캐시와 사용자 데이터를 모두 지웁니다 |
| 프록시 | 허용 출처를 배포 도메인으로 좁힙니다 |
