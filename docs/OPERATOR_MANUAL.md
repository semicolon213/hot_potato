# Hot Potato ERP 운영자 매뉴얼

> 개발 단계: **⑦ 수정 및 문서화** · 산출물: 운영자 매뉴얼
> 대상: 학과 조교 또는 시스템 관리자(`is_admin = O`)
> 기준: `main` @ `ffed6c7` (2025-12-01). 화면 이름과 버튼 이름은 이 시점 코드 기준입니다.
> 장애가 났을 때는 [RUNBOOK.md](./RUNBOOK.md)를 보세요.

## 1. 운영자가 하는 일

| 주기 | 작업 | 어디서 |
|---|---|---|
| 최초 1회 | 초기 세팅, 첫 관리자 만들기 | Apps Script 편집기, `hp_member` 스프레드시트 |
| 학기 초 | 신입생·신규 교직원 사전 등록, 가입 승인 | 앱 > 관리자 |
| 수시 | 가입 승인, 고정 공지 승인, 기본 템플릿·기본 태그·결재 템플릿 관리, 학사 일정 설정 | 앱 > 관리자, 문서, 일정 |
| 수시 | Google 그룹 멤버 추가 | Google Groups (승인 안내 메일을 받은 그룹 관리자) |
| 매일 (자동) | 관리자 키 갱신 | Apps Script 트리거 |
| 수시 | 데이터 확인·수정 | Google Drive의 스프레드시트 |

## 2. 최초 세팅

1. [DEPLOYMENT.md](./DEPLOYMENT.md) 1~5단계를 끝냅니다. 특히 §3.2의 수동 작업(`SPREADSHEET_ID` 속성, `admin_keys` 시트, 트리거, 역할 폴더 공유)을 빠뜨리지 않습니다.
2. **관리자 키를 처음 만듭니다.** Apps Script 편집기에서 `handleDailyKeyUpdate`를 한 번 직접 실행합니다. `hp_member.admin_keys` 2행에 키가 생깁니다.
3. **첫 관리자를 사전 등록합니다.** `hp_member` 스프레드시트의 `user` 시트에 한 행을 넣습니다: `no_member`(학번/교번, 숫자 8~15자리), `name_member`(이름, 그 사람 Google 계정의 이름과 똑같이)만 채우고 나머지 칸은 비웁니다.
4. 첫 관리자가 앱에 로그인합니다. **회원가입** 화면에서 학번/교번과 **가입유형**을 넣고 가입합니다.
5. `user` 시트에서 그 행을 직접 고칩니다. 승인해 줄 관리자가 아직 없기 때문입니다.
   - `Approval` → `O`
   - `approval_date` → 오늘 날짜
   - `is_admin` → `O`
6. 다시 로그인하면 사이드바에 **관리자** 메뉴가 보입니다.

> 기준 시점 코드에서는 가입 화면의 **관리자로 가입하기** + **관리자 키**로 신청해도 `is_admin`이 `O`로 저장되지 않습니다(BUG-10). 관리자 권한은 항상 5단계처럼 시트에서 직접 줍니다.

## 3. 회원 관리

관리자 화면 위쪽 카드와 탭은 `user` 시트의 `Approval` 값으로 나뉩니다.

| 탭 | `Approval` 값 | 뜻 |
|---|---|---|
| **승인 대기 사용자** | `X` | 가입 신청을 마친 사람 |
| **승인된 사용자** | `O` | 사용 중인 사람 |
| **미사용 사용자** | 빈 칸 | 사전 등록만 되어 있고 아직 가입하지 않은 사람 |
| **고정 공지 승인 요청** | — | 공지 고정 요청 (§4) |

### 3.1 사전 등록

학번·이름이 등록되어 있어야 가입 신청을 할 수 있습니다. 가입 화면의 이름 칸은 **Google 계정의 이름**으로 채워지고 고칠 수 없습니다. 사전 등록한 이름과 앞뒤 공백을 뺀 값이 정확히 같아야 합니다. 다르면 가입할 때 "등록되지 않은 학번이거나 학번과 이름이 일치하지 않습니다. 정보를 확인해주세요." 메시지가 나옵니다.

1. **관리자** 화면에서 **사용자 일괄 추가**를 누릅니다(고정 공지 탭에서는 버튼이 숨겨집니다).
2. 둘 중 하나를 고릅니다.
   - **직접 입력**: **항목 추가**로 줄을 늘리고 학번/교번과 이름을 넣습니다.
   - **엑셀 파일 업로드**: **엑셀 양식 다운로드**로 `사용자_일괄_추가_양식.xlsx`를 받아 채운 뒤 **엑셀 파일 선택**으로 올립니다. 헤더는 `학번/교번`, `이름`이어야 합니다.
3. **추가**를 누릅니다. 학번/교번은 8~15자리 숫자여야 하고, 이미 있는 학번은 건너뜁니다.

### 3.2 가입 승인

1. **승인 대기 사용자** 탭에서 대상의 **승인**을 누릅니다.
2. **사용자 승인 및 그룹스 권한 설정** 창이 뜹니다. **가입유형**은 사용자가 신청한 값이 기본으로 선택되어 있습니다. 필요하면 바꿉니다.
3. **승인 및 그룹스 추가**를 누릅니다.
   - `user` 시트의 `Approval`이 `O`, `approval_date`가 오늘 날짜가 됩니다.
   - 고른 역할의 Google 그룹 주소로 **멤버 추가 요청 메일**이 배포 계정에서 나갑니다. **그룹에 자동으로 추가하지는 않습니다.** 그룹 관리자가 메일을 보고 Google Groups에서 직접 추가해야 합니다.
   - 처리 기록은 `hp_member.group_management_log` 시트에 `NOTIFICATION_SENT`로 남습니다.
4. 사용자는 **로그아웃 후 다시 로그인**해야 승인 상태가 반영됩니다. **승인 대기 중** 화면은 자동으로 새로 고쳐지지 않습니다.

> 승인 창에서 고른 가입유형은 그룹 안내 메일에만 쓰이고 `user_type` 열은 바꾸지 않습니다. 역할을 바꾸려면 `user` 시트의 `user_type`도 함께 고칩니다(`student`, `std_council`, `supp`, `professor`, `ad_professor`).
> 역할별 그룹 주소는 `CONFIG.gs`의 `GROUP_ROLE_MAPPING`에 있습니다.

### 3.3 가입 거부

기준 시점 코드에서는 **거부** 버튼이 서버에서 처리되지 않고 실패합니다(BUG-02). 거부해야 할 때는 `user` 시트에서 그 행의 `user_type`, `google_member`, `Approval`, `is_admin`을 비웁니다. 그러면 **미사용 사용자**(사전 등록 상태)로 돌아갑니다. 사전 등록 자체를 없애려면 행을 지웁니다.

### 3.4 관리자 추가

- 이미 가입한 사용자를 관리자로 바꾸려면 `user` 시트의 `is_admin`을 `O`로 고칩니다. 대상은 다시 로그인해야 **관리자** 메뉴가 보입니다.
- 관리자 화면의 **관리자 키 이메일 전송** 영역(**관리자 키 전송** 버튼)은 기준 시점 코드에서 키를 받아 오지 못해 "이메일 전송에 실패했습니다"로 끝납니다(BUG-12). 관리자 추가는 위 방법을 씁니다.

## 4. 콘텐츠 관리

| 작업 | 위치 | 비고 |

| 기본 템플릿 수정·삭제 | 새 문서 화면의 기본 템플릿 카드 (관리자에게만 편집·삭제 표시) | |
| 기본 태그 추가·수정·삭제 | 새 문서 화면의 카테고리 탭에서 **기본 태그명** 입력 후 **추가** (관리자 전용) | `static_tag.tag` 시트에 저장 |

| 학생·교직원 명단 | **학생 및 교직원** → **학생**(**학생 추가**, **일괄 업로드**), **교직원**(**교직원 추가**), **학과 위원회**(**학과 위원회 추가**) | `student`, `staff` 스프레드시트에 저장 |

## 5. 회계 장부

1. 사이드바 **회계**는 가입유형이 집행부(`std_council`), 조교(`supp`), 교수(`professor`)인 사용자에게만 보입니다.
2. **새 장부** 카드를 누르면 **새 장부 만들기** 창이 뜹니다. 장부 이름, 통장 이름, 최초 잔액 (원), 주관리인, 별도 관리인, 접근 권한(개인 사용자, 역할 그룹)을 정하고 **생성**을 누릅니다.
3. `hot potato/회계/{장부 이름}/` 폴더, `{장부 이름}_장부` 스프레드시트, `증빙/` 폴더가 생기고 지정한 사람·그룹에 공유됩니다.
4. 접근 권한은 Drive 공유로 관리됩니다. 사람을 추가하거나 빼려면 장부 폴더의 공유 설정을 바꿉니다.
5. 예산 계획은 **작성(`pending`) → 별도 관리인 검토(`reviewed`) → 주관리인 승인(`approved`) → 집행(`executed`)** 순서로 처리됩니다. 반려되면 `rejected`가 됩니다.

## 6. 데이터 직접 수정 시 주의

Google Sheets가 DB이므로 운영자가 시트를 직접 고칠 수 있습니다. 다만 아래를 지켜야 합니다.

- **헤더(1행)와 열 순서를 바꾸지 않습니다.** 코드가 헤더 이름과 열 위치로 읽습니다. `initializeSystem`을 다시 실행하면 다른 헤더는 코드 기준으로 덮어씌워집니다.
- `user.google_member`, `notice.writer_email`, 학생·교직원 연락처는 **변환된 값**으로 저장됩니다. 평문으로 덮어쓰지 않습니다.
- 스프레드시트나 폴더의 **이름을 바꾸지 않습니다.** 앱이 이름으로 파일을 찾습니다. 바꿔야 한다면 Netlify 환경변수(`VITE_*_SPREADSHEET_NAME` 등)와 스크립트 속성도 함께 바꿉니다.
- 배포 계정 드라이브 **어디에도** 같은 이름의 스프레드시트를 두지 않습니다. 백엔드는 폴더와 상관없이 이름으로 검색해 첫 번째 파일만 씁니다. 휴지통에 있는 파일은 제외됩니다.
- 큰 수정 전에는 **파일 → 사본 만들기**로 백업합니다. Google Sheets의 **버전 기록**으로도 되돌릴 수 있습니다.

## 7. 설정값 위치

| 설정 | 위치 |
|---|---|
| 폴더·시트 이름(서버) | Apps Script → 프로젝트 설정 → 스크립트 속성 |
| `hp_member` 위치 | 스크립트 속성 `SPREADSHEET_ID` |
| 역할별 그룹 이메일(서버) | `appScript/CONFIG.gs`의 `GROUP_ROLE_MAPPING` (코드 수정 후 재배포) |
| 폴더·시트 이름, 그룹 이메일(프론트) | Netlify 환경변수 `VITE_*` |
| Apps Script 주소 | Netlify 환경변수 `VITE_APP_SCRIPT_URL` (또는 `APP_SCRIPT_URL`) |
| 학사 일정 | 앱 학사 일정 설정 창 (해당 캘린더 스프레드시트에 저장) |
| 관리자 키 갱신 주기 | Apps Script 트리거 |
