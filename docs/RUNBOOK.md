# Hot Potato ERP 런북 (장애 대응)

> 개발 단계: **⑦ 수정 및 문서화** · 산출물: 장애 대응 가이드
> 대상: 운영자(조교), 개발 담당자
> 기준: `main` @ `ffed6c7` (2025-12-01). 메시지 문구는 이 시점 코드 기준입니다.

각 항목은 **대상·조건 → 사전 확인 → 절차 → 판단·분기 → 해결되지 않을 때 → 완료 확인** 순서로 적었습니다.

## 0. 공통 사전 확인

장애 신고를 받으면 먼저 아래를 확인합니다.

| 확인 | 방법 |
|---|---|
| 영향 범위 | 한 사람만인가, 전체인가? 다른 계정·브라우저에서도 같은가? |
| 증상 화면 | 사용자에게 화면 캡처와 **개발자 도구(F12) → Console** 캡처를 받습니다 |
| 최근 변경 | Netlify **Deploys**의 마지막 배포 시각, Apps Script **배포 관리**의 버전, 최근 커밋 |
| 필요 권한 | Netlify 사이트 관리자, Apps Script 배포 계정, Google Cloud OAuth 클라이언트 편집 권한 |

| 확인 위치 | 볼 것 |
|---|---|
| 브라우저 Console | `API 요청 시도`, `✅ API 응답 성공`, `⚠️ API 응답 실패`, 빨간 오류 |
| 브라우저 Network | `/.netlify/functions/proxy`의 상태 코드와 응답 본문 |
| Netlify → Logs → Functions → `proxy` | `❌ APP_SCRIPT_URL 환경 변수가 설정되지 않았습니다.`, `❌ 프록시 오류:` |

| Apps Script 웹 앱 URL을 브라우저로 직접 열기 | `Hot Potato App Script is running`이 나오면 배포는 살아 있음 |

## RB-01 모든 기능에서 데이터가 안 불러와짐

**대상·조건:** 전체 사용자에게 공지·결재·문서가 비어 있거나 오류 알림이 뜹니다.

**사전 확인:** §0의 웹 앱 URL 직접 열기로 Apps Script 배포가 살아 있는지 봅니다.

**절차:**
1. Network 탭에서 `/.netlify/functions/proxy` 응답을 확인합니다.
2. 응답에 따라 분기합니다.

**판단·분기:**

| 응답 | 원인 | 조치 |
|---|---|---|
| 500 `서버 설정 오류: Apps Script URL이 설정되지 않았습니다.` | Netlify에 `VITE_APP_SCRIPT_URL`과 `APP_SCRIPT_URL`이 모두 없음 | Netlify 환경변수에 `VITE_APP_SCRIPT_URL` 추가 → **Clear cache and deploy** |
| 200 + `success:false`, `error`에 HTML 문서가 들어 있음 | Apps Script가 JSON 대신 HTML(로그인·권한·오류 페이지)을 돌려줌. 배포가 삭제됐거나, 액세스 권한이 "모든 사용자"가 아니거나, URL이 옛날 배포를 가리킴 | Apps Script **배포 관리**에서 활성 배포 URL과 액세스 권한을 확인하고 Netlify 값과 비교 → 다르면 고치고 재배포 |
| 500 `프록시 오류: ...` | 네트워크 또는 Google 측 일시 장애 | 5분 후 재시도. [Google Workspace 상태 대시보드](https://www.google.com/appsstatus) 확인 |
| 200 + `success:false`, `알 수 없는 액션입니다: <액션>` | 프론트가 백엔드에 없는 액션을 호출. 프론트만 먼저 배포됐거나 Apps Script에 새 버전을 올리지 않음 | Apps Script 새 버전 배포, 또는 Netlify 이전 배포로 롤백 |
| 200 + `success:false`, 그 외 메시지 | 액션 처리 중 오류 | Apps Script **실행** 로그에서 해당 시각의 오류 확인 → RB-03 또는 개발 담당자 |

**해결되지 않을 때:** 직전 배포를 롤백합니다(RB-06). 그래도 안 되면 개발 담당자에게 Console·Network 캡처와 Functions 로그를 전달합니다.

**완료 확인:** 새 창에서 로그인 → 공지사항 목록이 보이고 proxy 응답이 `success:true`.

## RB-02 로그인·가입이 안 되거나 자꾸 로그아웃됨

**대상·조건:** 로그인 버튼을 눌러도 앱으로 못 돌아오거나, 가입이 거절되거나, 사용 중에 로그아웃됩니다.

**판단·분기:**

| 증상 | 원인 | 조치 |
|---|---|---|
| Google 화면에 `redirect_uri_mismatch` | 접속 주소가 OAuth 클라이언트에 등록되지 않음 (도메인 변경, 새 포트) | Google Cloud Console → OAuth 클라이언트 → 원본과 리디렉션 URI에 현재 주소 추가. 반영까지 몇 분 걸릴 수 있음 |
| Google 화면에 `client_id` 누락 오류 | 빌드 시 `VITE_GOOGLE_CLIENT_ID`가 없었음 | Netlify 환경변수 추가 → Clear cache and deploy |
| Google 화면에 `access_denied` 또는 "앱이 확인되지 않음" | OAuth 동의 화면이 테스트 모드이고 사용자가 테스트 사용자가 아님 | 동의 화면을 게시하거나 테스트 사용자에 추가 |
| 약 1시간 후 "토큰이 만료되었습니다. 다시 로그인해주세요." 알림과 함께 로그아웃 | implicit flow라 갱신 토큰이 없어 자동 갱신이 실패함. **정상 동작** | 다시 로그인하라고 안내 |
| 30분 동안 아무것도 안 했더니 "세션이 만료되었습니다. 다시 로그인해주세요." | 무활동 세션 만료. **정상 동작** | 다시 로그인 |
| 로그인 후 계속 **승인 대기 중** 화면 | 아직 승인되지 않았거나, 승인됐지만 화면이 새로 고쳐지지 않음 | `user` 시트에서 `Approval` 확인 → `O`면 **로그아웃** 후 다시 로그인 |
| 가입 시 "등록되지 않은 학번이거나 학번과 이름이 일치하지 않습니다. 정보를 확인해주세요." | 사전 등록이 안 됐거나, 등록한 이름이 Google 계정 이름과 다름 | [OPERATOR_MANUAL §3.1](./OPERATOR_MANUAL.md#31-사전-등록)대로 사전 등록. `name_member`를 Google 계정 이름과 똑같이 맞춤 |
| 가입 시 "유효하지 않은 학번 형식입니다." | 학번/교번이 8~15자리 숫자가 아님 | 올바른 번호로 다시 입력. 사전 등록 값도 같은 형식인지 확인 |
| 관리자로 가입했는데 **관리자** 메뉴가 없음 | 기준 시점 코드는 가입 시 `is_admin`을 `O`로 저장하지 않음 (BUG-10) | `user` 시트의 `is_admin`을 `O`로 고치고 다시 로그인 |

**해결되지 않을 때:** 사용자 Console의 `checkUserStatus`·`registerUser` 응답을 캡처해 개발 담당자에게 전달합니다.

**완료 확인:** 해당 사용자가 대시보드까지 들어옵니다.

## RB-03 "데이터 로딩 중"에서 멈추거나 특정 화면이 비어 있음

**대상·조건:** 로그인 후 데이터 동기화 진행 표시가 오래 멈춰 있거나, 특정 화면(공지, 캘린더, 학생, 교직원, 회계)이 비어 있습니다. Console에 `⚠️ 찾지 못한 스프레드시트:`, `❌ 스프레드시트 ID 조회 실패:`, `... spreadsheet ID not found` 같은 메시지가 나옵니다.

**사전 확인:** 배포 계정으로 Google Drive에 들어가 `hot potato/` 폴더 구조를 확인합니다([DEPLOYMENT.md §3.1](./DEPLOYMENT.md#31-initializesystem-실행)).

**절차:**
1. Console에서 어떤 스프레드시트를 못 찾았는지 확인합니다(`찾지 못한 스프레드시트` 목록).
2. 배포 계정 Drive에서 그 파일이 **정확한 이름**으로 있는지, 휴지통에 들어가지 않았는지 확인합니다.
3. 사용자가 그 파일에 접근 권한이 있는지 확인합니다. 캘린더·학생·교직원·장부 시트는 브라우저에서 사용자 권한으로 직접 읽습니다.
4. 회원·관리자 기능만 실패하면 Apps Script 스크립트 속성 `SPREADSHEET_ID`가 `hp_member`의 ID와 같은지 확인합니다.

**판단·분기:**

| 확인 결과 | 조치 |
|---|---|
| `calendar_professor`만 없음 | `initializeSystem`이 만들지 않는 파일입니다. [DEPLOYMENT.md §3.2](./DEPLOYMENT.md#32-initializesystem이-하지-않는-일-수동)대로 직접 만듦 |
| 다른 파일이 없음 | Apps Script에서 `initializeSystem` 다시 실행. 있는 파일은 건너뛰고 없는 것만 만듭니다. 단, 헤더가 다른 기존 시트는 1행이 코드 기준으로 덮어씌워지므로 먼저 사본을 만듦 |
| 이름이 다름 | 원래 이름으로 되돌리거나, Netlify 환경변수(`VITE_*_SPREADSHEET_NAME`)와 스크립트 속성을 함께 바꾼 뒤 재배포 |
| 같은 이름 파일이 여러 개 | 하나만 남기고 이름을 바꾸거나 삭제. 백엔드는 폴더와 상관없이 첫 번째로 찾은 파일만 씁니다 |
| 사용자에게 권한이 없음 | 해당 역할 폴더를 사용자 또는 역할 그룹에 공유. 승인 후 그룹 추가가 처리됐는지 `hp_member.group_management_log`와 Google Groups 멤버 목록 확인 |
| 오류 없이 진행 표시만 멈춤 | 헤더의 동기화 새로고침 버튼 또는 브라우저 새로고침. 계속되면 RB-04 확인 |

**해결되지 않을 때:** Console 전체 로그를 저장해 개발 담당자에게 전달합니다.

**완료 확인:** 로딩 표시가 사라지고 해당 화면 데이터가 보입니다.

## RB-04 느려지거나 "API 호출 제한 초과"

**대상·조건:** 응답이 매우 느리거나, Console에 `429`, `⚠️ API 호출 제한 초과 (429)`, `sync429Error`, `Quota exceeded`가 나옵니다.

**원인:** Apps Script와 Google API는 계정별 호출 할당량이 있습니다. 학기 초처럼 사용자가 몰리면 초과할 수 있습니다.

**절차:**
1. 앱이 스스로 대응합니다. 429를 받으면 `Retry-After`가 있으면 그 시간만큼, 없으면 점점 길게 기다렸다가 재시도합니다. 백그라운드 동기화는 해당 데이터 종류를 30분부터 최대 120분까지 멈춥니다.
2. 사용자에게 잠시 후 다시 시도하라고 안내합니다. 새로고침을 반복하면 더 늦어집니다.
3. Apps Script **실행** 화면에서 실패 비율과 6분 초과(`Exceeded maximum execution time`) 오류를 확인합니다.

**해결되지 않을 때:** 하루 단위 할당량을 넘었으면 다음 날 자동으로 풀립니다. 반복되면 개발 담당자에게 캐시 TTL과 동기화 주기 조정을 요청합니다(`src/utils/cache/cacheUtils.ts`, `src/services/dataSyncService.ts`).

**완료 확인:** 새로 연 창에서 공지사항이 10초 안에 보입니다.

## RB-05 결재·문서 링크를 열면 "액세스 권한 필요"

**대상·조건:** 결재선에 있는데 문서를 열 수 없습니다.

**절차:**
1. 결재 요청자에게 문서가 **공유 문서**인지 **개인 문서**인지 확인합니다. 개인 문서는 요청자의 드라이브에 있으므로 요청자가 권한을 줘야 합니다.
2. 요청자의 문서를 Drive에서 열고 **공유**에 결재 참여자가 있는지 확인합니다.
3. 없으면 요청자가 직접 보기 권한으로 공유합니다.

**완료 확인:** 결재 참여자가 문서를 엽니다.

## RB-06 잘못된 배포 되돌리기

**대상·조건:** 배포 직후 기능이 깨졌습니다.

**절차:**

| 대상 | 롤백 |
|---|---|
| 프론트엔드 | Netlify **Deploys** → 직전 정상 배포 → **Publish deploy** |
| Apps Script | **배포 관리 → 기존 배포 편집 → 버전**에서 직전 버전 선택 → 배포 (URL 유지) |
| 환경변수 | Netlify 환경변수를 이전 값으로 되돌림 → Clear cache and deploy |

**판단·분기:** 프론트와 백엔드를 같이 배포했다면 **둘 다** 이전 버전으로 돌립니다. 한쪽만 돌리면 액션 이름이 어긋날 수 있습니다.

**해결되지 않을 때:** 롤백 후에도 같은 증상이면 배포가 원인이 아닙니다. RB-01부터 다시 확인합니다.

**완료 확인:** [DEPLOYMENT.md §6](./DEPLOYMENT.md#6-배포-후-확인) 체크리스트를 다시 통과합니다.
